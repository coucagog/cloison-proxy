# CLOISON N0 — Kit moteur léger (daemon desktop)

> N0 = **le moteur descend chez le client** : l'opérateur ne lit rien (promesse
> absolue, charte §4). Le cloud ne reste qu'un plan de contrôle **aveugle**.
> Ce document est le guide d'installation et d'utilisation du daemon desktop
> N0 v1, et la déclaration **honnête** de ses limites (charte §11, N0-PREP).

---

## 1. Ce que N0 v1 est

Un **daemon local** (binaire `cloison-proxy` en mode N0) qui expose un endpoint
**compatible OpenAI** sur `http://localhost:8787`. Votre interface IA
(Open WebUI, LibreChat, bolt.diy, agents…) s'y branche avec **deux champs** :

```
Base URL : http://localhost:8787/v1
Clé      : mn_<jeton_local>.<clé_amont>
```

Toute PII détectée est remplacée par une sentinelle `⟦…⟧` **avant** d'atteindre
le fournisseur LLM, puis restaurée dans la réponse. Le **coffre** (table
jeton ↔ valeur) vit **chez vous**, chiffré sur disque ; le fournisseur et
l'opérateur ne voient jamais le clair.

**Architecture** : le moteur est **Rust seul** (`cloison-core` : détection
structurée + gazetteers + Luhn + généralisation). **Aucun sidecar NER Python**
n'est requis (charte §4 : le sidecar est pour les paliers serveur/enclave).
Zéro dépendance au plan de contrôle pour masquer : l'auth est **100 % locale**.

## 2. Installation

Le binaire est `cloison-proxy` (même binaire que l'edge, rôle `edge`).

```bash
# Depuis le dépôt (ou une release) :
cargo build --release -p cloison-proxy
# → target/release/cloison-proxy  (binaire unique, ~8 Mo en release)

# Répertoire local N0 :
mkdir -p ~/.cloison
```

## 3. Configuration (mode N0)

Le mode N0 s'active en posant `CLOISON_VAULT_PATH`. Exemple de lancement :

```bash
export CLOISON_ROLE=edge
export CLOISON_LISTEN_ADDR=127.0.0.1:8787          # local uniquement
export CLOISON_UPSTREAM_BASE_URL=https://openrouter.ai/api/v1   # votre fournisseur
export CLOISON_VAULT_PATH=~/.cloison/vault.redb    # coffre persistant
export CLOISON_VAULT_PASSPHRASE='votre-passphrase' # clé du coffre (jamais persistée)
export CLOISON_EXPECTED_ACCESS_TOKEN=mon_jeton      # jeton mn_ local
export CLOISON_TENANT_KEY_HEX=$(openssl rand -hex 32)  # clé locataire
cloison-proxy
```

Variables N0 (détails : `docs/CONFIG.md` §1) :

| Variable | Rôle | Note |
|---|---|---|
| `CLOISON_VAULT_PATH` | **active le mode N0** | coffre redb persistant chiffré AES-256-GCM |
| `CLOISON_VAULT_PASSPHRASE` | clé du coffre | dérivée par HKDF ; **requise**, jamais stockée en clair |
| `CLOISON_VAULT_TTL_SECS` | TTL du coffre | défaut 7 jours |
| `CLOISON_SESSION_SALT_FILE` | sel persistant | défaut `<vault_path>.salt` (0600) — la session survit aux redémarrages |
| `CLOISON_EXPECTED_ACCESS_TOKEN` | jeton `mn_*` local | comparé à temps constant ; aucun appel au plan de contrôle |
| `CLOISON_AUDIT_MODE` | **0 par défaut** | l'audit k-anonyme vers le journal est **opt-in** (`=1`) |
| `CLOISON_VAULT_TTL_SECS` | purge | les entrées expirées sont purgées par le TTL |
| `CLOISON_ALIAS_EXPANSION` *(v1.1)* | alias intra-session | **1 par défaut** (R1–R7, in-core) — jamais les pronoms, scores plafonnés |
| `CLOISON_QUASI_ID_GAUGE` *(v1.1)* | jauge quasi-id | **0 par défaut** (opt-in) — signal de densité, jamais de résolution |
| `CLOISON_QUASI_ID_THRESHOLD` *(v1.1)* | seuil de la jauge | défaut `0.5` (`score > seuil` strict ; `1.0` = désactivée de fait) |
| `CLOISON_ALIAS_MAX_MENTIONS` *(v1.1)* | borne de session | défaut 200 mentions canoniques (FIFO) |
| `CLOISON_VAULT_KEYCHAIN_SERVICE` *(v1.1 ②)* | passphrase du coffre | **posé = keychain OS** (Credential Manager / Keychain / Secret Service-keyutils) — jamais en clair par CLOISON ; repli env avec warn, fail-loud si rien |
| `CLOISON_VAULT_KEYCHAIN_USER` *(v1.1 ②)* | compte keychain | défaut `default` |

**Comportements garantis :**
- **Fail-loud au boot** : passphrase absente, mauvaise passphrase ou coffre
  corrompu → le daemon **refuse de démarrer** (jamais de recréation silencieuse).
  Depuis **v1.1 ②**, la passphrase peut venir du **keychain OS**
  (`CLOISON_VAULT_KEYCHAIN_SERVICE`) : stockée **chiffrée par l'OS**, jamais
  en clair par CLOISON ; premier démarrage = stockage de l'env dans le
  keychain, ensuite le keychain fait foi.
- **Sel de session persistant** : vos conversations restent restaurables à
  travers les redémarrages du daemon (le sel est dans `<vault_path>.salt`,
  0600). Pour **tourner le sel** (rotation, non-liabilité inter-sessions) :
  supprimer ce fichier puis redémarrer — les anciens jetons ne seront plus
  restaurés (marqueur neutre `[REDACTED]`, jamais de jeton brut).
- **Généralisation des faibles cardinalités** : date → `YYYY-MM`, IP →
  `[IP]`, carte bancaire → `•••••••••1234`, **ville** → `[VILLE_SN]`. Ces
  valeurs ne sont **jamais** tokenisées (la fréquence trahirait le jeton).

## 4. Limites honnêtes (charte §11 — à lire avant d'acheter)

1. **Rappel PERSON/LOC réduit sans sidecar NER.** En N0, le moteur est
   Rust seul : la détection des **noms** (hors gazetteers `nom_sn`) et des
   **lieux** (hors gazetteers `ville_sn`) en **texte libre** est **réduite**
   par rapport aux paliers serveur (N1/N3 + `cloison-detect` : Presidio +
   GLiNER + afroxlmr, le fossé GO mesuré). Les emails, téléphones
   (+221 70/71/72/75/76/77/78/79, fixes 30/32/33/36), CNI (Luhn), cartes
   bancaires, IP, dates, passeports/permis/matricules (contextuels) et les
   noms/toponymes des gazetteers sont **couverts**. Depuis **N0 v1.1**,
   l'**alias intra-session** masque en plus les formes dérivées des mentions
   déjà établies (diminutifs, titres, variantes casse/diacritiques) — un nom
   **hors gazetteer** et jamais mentionné reste toutefois un risque de clair :
   c'est la limite assumée (la voie ONNX de `cloison-detect` est la rampe
   vers un NER léger embarqué, documenté — pas livré ici).
2. **Poste compromis.** N0 ne protège pas contre un malware ou un vol de la
   machine : le coffre **et** la clé y vivent. À écrire dans votre promesse.
3. **Quasi-identifiants.** « Le patient de 42 ans opéré le 3 mars à
   Ziguinchor » ré-identifie sans nom. N0 **signale** la densité (jauge
   quasi-id in-core, N0 v1.1 — opt-in `CLOISON_QUASI_ID_GAUGE=1`), il ne
   prétend pas résoudre (charte §11).
4. **PII hallucinée.** Le modèle peut inventer une PII **sans** jeton
   (grounding) — non résoluble par le proxy seul (item de recherche, charte
   §16). Les sentinelles forgées ne sont **jamais** restaurées (registre
   d'émission + MAC, invariant I3).
5. **`/v1/embeddings` bloqué.** Un embedding de PII reste dérivé de PII
   (charte §7.1) : la route est **absente** (404). Piste documentée :
   tokeniser avant embedding (perte de sens assumée) — non livrée.
6. **Restauration bornée à la requête.** On ne restaure que les jetons émis
   pour la requête en cours (registre + MAC) : un jeton d'une requête
   antérieure n'est jamais restauré (anti-collision, invariant I3).

## 5. Vérifier que ça marche

```bash
# Sans LLM réel, un mock d'écho suffit :
curl -s http://localhost:8787/v1/chat/completions \
  -H "Authorization: Bearer mn_<jeton>.<clé_amont>" \
  -H "Content-Type: application/json" \
  -d '{"model":"x","messages":[{"role":"user","content":
       "Contact: Aminata Diop, user@example.com, tel +221 77 123 45 67"}]}'
# → la réponse contient « Aminata Diop, user@example.com, +221 77 123 45 67 »
#   (restaurés) et aucune sentinelle ⟦…⟧ résiduelle.
```

Le coffre (`~/.cloison/vault.redb`) ne contient **aucune valeur en clair**
(chiffré AES-256-GCM) : `grep Aminata ~/.cloison/vault.redb` ne trouve rien.

## 6. Rapport au plan de contrôle (opt-in)

En N0, le masquage ne dépend **jamais** du cloud. L'audit k-anonyme (reçus
signés, compteurs uniquement, jamais de texte — invariant I9) est **opt-in** :
`CLOISON_AUDIT_MODE=1` + `CLOISON_AUDIT_KEYS` + un wiring contrôle
(`CLOISON_CONTROL_URL`, `docs/DEPLOY.md` §11) si vous voulez alimenter le
journal de transparence public. Par défaut : **aucun** reçu ne sort de la
machine.

## 7. N0 v1.1 — alias intra-session + jauge quasi-id (livrés) ; pistes restantes

**Livré (in-core, Rust seul) :**
- **Alias intra-session (règles R1–R7)** : une mention canonique établie dans la
  conversation (ex. « Mamadou » détecté par le gazetteer) masque ensuite ses
  formes dérivées — prénom seul, titre + nom, nom seul (hors noms communs),
  **diminutifs** (ex. « Momo »), raccourcis de lieux (ex. « Ouaga »), variantes
  casse/diacritiques. **Jamais les pronoms** (charte §6.1 couche 4 : « elle »
  n'est pas une fuite), scores plafonnés (`×0.85`, boost borné). Actif par
  défaut en N0 (`CLOISON_ALIAS_EXPANSION`, défaut `1`).
- **Jauge quasi-id (4 catégories : âge + acte + date + lieu)** : densité
  fenêtrée, `flagged = score > seuil` — **signal, jamais de résolution**
  (charte §6.1 couche 6, §11). **Opt-in** (`CLOISON_QUASI_ID_GAUGE=1`,
  `CLOISON_QUASI_ID_THRESHOLD`, défaut `0.5`). Sortie : compteur + log
  (jamais de texte).
- **Keychain OS pour la passphrase du coffre (chantier ②)** :
  `CLOISON_VAULT_KEYCHAIN_SERVICE` posé → la passphrase est lue/stockée dans
  le keychain OS (Windows Credential Manager / macOS Keychain / Linux Secret
  Service-keyutils) — **jamais persistée en clair par CLOISON** (l'OS la
  chiffre). Repli `CLOISON_VAULT_PASSPHRASE` avec warn ; ni keychain ni env
  → **refus de démarrer** (fail-loud inchangé).
- **Module navigateur `@cloison/core` (chantier ③)** : `cloison-wasm`
  ré-exporte les bindings wasm-bindgen du core (`cloisonInitSession`,
  `cloisonTokenize`, `cloisonRestore`, …) pour **tokenize/restore
  in-browser** — **coffre in-memory** (0 valeur persistée en clair),
  **zéro secret dans la page** (clé locataire générée côté client). Page de
  démo : `deploy/wasm-demo/index.html` (build via `wasm-pack`, porte de
  vérification `cargo check --target wasm32-unknown-unknown`).

**Pistes v1.1 restantes (documentées, non livrées) :**
- NER léger embarqué (voie ONNX de `cloison-detect`) pour le rappel
  PERSON/LOC en texte libre (arbitrage GO/NO-GO).
- Déclinaison mobile embarqué (même moteur que le navigateur).
