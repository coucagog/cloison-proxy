Le produit · architecture

Un proxy entre votre interface et le modèle : rien d'autre ne change.

CLOISON est compatible OpenAI : la plupart des interfaces IA se branchent en deux champs. Ce qui change, c'est ce que le fournisseur reçoit — et ce que l'opérateur peut prouver.

1 · Le flux

Interface IA ──▶ CLOISON edge ──▶ Fournisseur LLM
                 pseudonymise PII      ne reçoit QUE des jetons ⟦…⟧
                 restaure valeurs ◀─── réponse
                 (côté client)
  • À l'aller : noms, téléphones, emails, CNI, lieux… sont remplacés par des jetons ⟦…⟧ avant d'atteindre le fournisseur. Le modèle ne voit jamais la donnée personnelle en clair.
  • Au retour : les vraies valeurs sont restaurées dans la réponse que vous recevez. La conversation reste naturelle et cohérente — les jetons déterministes gardent la coréférence.
  • L'opérateur ne voit rien : le plan de contrôle ne manipule que des compteurs k-anonymes signés, jamais de texte (invariant I9).

2 · Le moteur de détection

La détection combine plusieurs sources, calibrées sur le français d'Afrique de l'Ouest (noms sénégalais, formats de CNI, toponymie, numéros +221) :

  • Moteur déterministe (regex + gazetteers + validations Luhn) : téléphones (+221 70/71/72/75/76/77/78/79, fixes 30/32/33/36), CNI, emails, cartes bancaires, IP, dates, passeports/permis/matricules (contextuels).
  • NER transformer (afroxlmr, MasakhaNER) pour PERSON/LOC en texte libre — validé par un benchmark public contre une baseline Presidio forte : verdict GO (PERSON 0.94 · LOC 0.84 · macro 0.95).
  • Consensus : une source seule sous seuil est refusée (spécificité mesurée 77 %).
  • Généralisation des faibles cardinalités : date → YYYY-MM, IP → [IP], carte → •••••••••1234, ville → [VILLE_SN] — jamais tokenisées (la fréquence trahirait le jeton).

4 · La promesse, vérifiable

« Nous ne lisons pas » n'est pas une clause contractuelle : c'est une propriété auditable.

  • Code ouvert : la passerelle (AGPL-3.0) et tous les composants vérifiables sont publiés sur github.com/coucagog/cloison-*.
  • Journal public : journal.wonkom.ai — chaque fenêtre d'audit est enregistrée (compteurs k-anonymes, chaîne de hachage, signatures Ed25519) et vérifiée dans votre navigateur (WASM), sans qu'aucune donnée ne quitte la page.
  • Rapport de conformité : en mode audit (observe-only), rapport k-anonyme signé par tenant, présentable à un DPO/auditeur.

5 · Des limites, dites honnêtement

Charte du projet : la transparence inclut les limites. Elles sont détaillées dans la FAQ — en résumé :

  • Quasi-identifiants (« le patient de 42 ans opéré le 3 mars à Ziguinchor ») peuvent ré-identifier sans nom : nous les signalons (jauge), nous ne prétendons pas les résoudre.
  • Poste compromis : en N0, un malware sur la machine sort du périmètre — le coffre et les clés y vivent.
  • PII hallucinée : le modèle peut inventer une PII sans jeton (grounding) — non résoluble par un proxy seul ; les sentinelles forgées ne sont jamais restaurées (registre + MAC).
