Journal de transparence

CLOISON tient un registre public de ce qu'elle fait de vos données. Ce que vous lisez ici est une description de ce registre — des preuves, jamais vos données. Chaque entrée répond à une seule question : comment vérifier que ça s'est réellement passé.

Cadre de référence

CLOISON s'inscrit d'abord dans notre cadre juridique de référence, pas dans un cadre importé. Soit la loi n°2008-12 sénégalaise sur la protection des données à caractère personnel, l'Acte additionnel CEDEAO A/SA.1/01/10 (applicable aussi dans l'espace UEMOA) et la Convention de Malabo 2014 de l'Union africaine. Ce cadre organise la protection autour d'un régime à deux étages de la CDP — déclaration ou autorisation préalable selon la nature du traitement — et maintient une distinction nette entre responsable de traitement et sous-traitant. Le RGPD intervient comme point de convergence à suivre, pas comme notre cadre principal.

01Ce que contient le journal

Le registre est découpé en fenêtres d'audit. Chaque fenêtre est un bloc immuable : il porte un horodatage de début et de fin, des compteurs agrégés, le hachage du bloc précédent et une signature Ed25519. Ajouter, retirer ou réécrire une requête après coup casserait la chaîne depuis sa racine — c'est cette propriété qui rend le journal vérifiable plutôt que simplement affirmé.

Les compteurs sont k-anonymes. Le registre dit combien, jamais qui. Les identifiants sont regroupés en ensembles d'au moins k individus ; en dessous de ce seuil, aucune personne ne se distingue des autres. C'est une agrégation, pas une liste.

Un contrat simple tient la page : jamais de texte, jamais de clair. Le registre contient des fenêtres, des compteurs, des hachages et des signatures — pas un mot de vos données.

02Vérification dans le navigateur

Cette page embarque un binaire WASM, cloison-verify, qui rejoue le journal. Il recalcule la chaîne, contrôle chaque signature Ed25519 et vérifie l'inclusion de chaque bloc dans la fenêtre. Tout le calcul s'exécute dans votre navigateur : aucune donnée ne quitte la page, aucune confiance n'est demandée.

shell
$ curl -s https://journal.wonkom.ai/2024-11.json > journal-2024-11.json
$ wasmtime run cloison-verify.wasm --journal journal-2024-11.json
128 blocs vérifiés · 0 divergence
javascript · wasm
import { verify } from "./cloison-verify.wasm";

const res = await fetch("/journal/2024-11.json");
const journal = await res.arrayBuffer();
const result = await verify(journal);

if (result.divergences.length === 0) {
  console.log(`${result.blocks.length} blocs vérifiés · 0 divergence`);
} else {
  console.error(result.divergences);
}
Aucune confiance demandée

Le binaire s'exécute chez vous, sur la machine qui affiche cette page. Vous n'avez pas à croire un tableau de bord, une capture ou une page de statut : cloison-verify recalcule et affiche le résultat, sans intermédiaire.

03Pourquoi c'est crédible

La crédibilité est une propriété, pas un ton. Trois choses la rendent concrète : le code de cloison-verify est public et auditable ; le journal est public et se télécharge sans inscription ; et la chaîne se recalcule à l'identique à partir des mêmes entrées.

  1. Le code est public. Auditez la logique de vérification ligne par ligne, sur n'importe quelle machine.
  2. Le journal est public. Aucun mur, aucune inscription — le registre se télécharge comme n'importe quel fichier.
  3. La chaîne est vérifiable. Toute divergence est signalée, pas tue. Une entrée qui diffère casse la chaîne, et ça se voit.

04Limites honnêtes

La transparence vaut aussi pour ce que le journal ne peut pas faire. Les compteurs sont agrégés : ils disent combien, pas qui, et ne permettent pas de reconstituer une requête individuelle. Un registre public prouve ce qui s'est passé, jamais ce qui n'a pas eu lieu — il ne démontre pas qu'une fuite n'existe pas ailleurs.

Pseudonymisation ≠ anonymisation

Un identifiant pseudonyme reste un identifiant. La pseudonymisation réduit le risque, elle ne le supprime pas. Dans notre cadre, le responsable de traitement reste responsable de bout en bout, et la pseudonymisation n'allège ni la déclaration ni l'autorisation préalable auprès de la CDP : elle ne transforme pas le responsable de traitement en sous-traitant.
